# Teacher Replay

Code for the paper *Teacher Replay: Effective and Verifiable Auditing of Prompt Use in Distilled Language Models*.

Teacher Replay lets a data owner test whether an open-weight model was post-trained on their prompts when
the responses were regenerated by a public teacher and the prompts were masked from the loss. The owner
splits the prompts at random into submitted and withheld sets before release. The auditor then replays the
teacher on every owner prompt, scores the replays under the suspect model and a few shadow students, and
runs an exact randomization test over the split.

## Install

```bash
pip install -e .                 # owner and audit tools (numpy, pandas, pyarrow)
pip install -e ".[models]"       # + torch, transformers, accelerate, trl (replay, score, train)
pip install -e ".[vllm]"         # optional vLLM backend for replay
```

## Usage

Inputs are tables (`.parquet`, `.jsonl` or `.csv`) with a string `id` column; a prompt file has columns
`id, prompt`. Commands print numbers only.

```bash
# 1. Owner, before release: random split and a hash commitment (publish only the digest)
teacher-replay split --prompts prompts.parquet --ids owner_ids.txt --arms S=0.5,H=0.5 \
  --out assignment.parquet --commitment commitment.json

# 2. Replay the teacher on the owner's prompts (default recipe: T=0.7, top-p 0.8, top-k 20, 1,536 tokens)
teacher-replay replay --teacher Qwen/Qwen3-32B --enable-thinking 0 --prompts prompts.parquet \
  --ids owner_ids.txt --seed 12 --out replays.parquet

# 3. Train shadow students on other public prompts with the same base, teacher and recipe
teacher-replay replay --teacher Qwen/Qwen3-32B --enable-thinking 0 --prompts prompts.parquet \
  --ids shadow_a_ids.txt shadow_b_ids.txt --seed 11 --out shadow_responses.parquet
teacher-replay train-shadow --base Qwen/Qwen2.5-7B --prompts prompts.parquet \
  --responses shadow_responses.parquet --ids shadow_a_ids.txt --out shadow_a
teacher-replay train-shadow --base Qwen/Qwen2.5-7B --prompts prompts.parquet \
  --responses shadow_responses.parquet --ids shadow_b_ids.txt --out shadow_b

# 4. Score the replays under the suspect and each shadow
for m in suspect/model shadow_a shadow_b; do
  teacher-replay score --model $m --prompts prompts.parquet --replays replays.parquet \
    --out scored_$(basename $m).parquet
done

# 5. Audit
teacher-replay audit --assignment assignment.parquet --method tr \
  --target scored_model.parquet --shadow scored_shadow_a.parquet --shadow scored_shadow_b.parquet \
  --B 10000 --alpha 0.01 --out audit.json
```

- `--method tr-l` gives the length-aware score, `--method tr-m` averages several replays (`replay --m 5`).
- `--stratify prompt_tokens,replay_tokens` relabels within strata of prompt and replay length.
- `--candidate NAME=TARGET,SHADOW[,SHADOW]` (repeatable) tests several candidate teachers with a Bonferroni correction.
- A shadow must never see an owner prompt. Run `teacher-replay <command> --help` for all options.

## Toy example

```bash
HF_HUB_OFFLINE=1 bash examples/toy_demo.sh
```

Runs the whole pipeline with Qwen2.5-0.5B (student) and Qwen2.5-0.5B-Instruct (teacher) on public
alpaca prompts in about 7 minutes on one 24 GB GPU. Outputs go to `toy_run/`. The toy uses a lower
teacher temperature (0.3) and a smaller training setup than the paper so that a 0.5B student shows a signal.
